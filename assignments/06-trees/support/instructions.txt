===========================================================
trees - TREE-BASED METHODS (real estate)
===========================================================

Data: trees_train_{student_id}.csv (n=300, 12 features +
sale_price_keur + distressed),
trees_test_{student_id}.csv (n=200, 12 features only).
Source: random subsample of the Ames Housing dataset (Kaggle,
De Cock 2011), with synthetic outcomes generated from those
features by a fixed (hidden) mechanism. Features carry their
real Ames names and units (sqft, year, room counts). The
distressed label is imbalanced; train prevalence ~ 0.15.

DATA DICTIONARY (12 features + 2 outcomes)
GrLivArea Living area, sqft.
LotArea Total lot size, sqft.
OverallQual Overall material and finish quality, 1-10 ordinal
(1 = very poor, 10 = excellent).
OverallCond Overall condition rating, 1-9 ordinal
(1 = very poor condition, 9 = excellent).
YearBuilt Original construction year.
YearRemodAdd Year of last remodel / addition (= YearBuilt if
no remodel).
TotalBsmtSF Total basement area, sqft (0 = no basement).
GarageArea Garage area, sqft (0 = no garage).
BedroomAbvGr Bedrooms above grade (basement bedrooms excluded).
Fireplaces Number of fireplaces.
WoodDeckSF Wood deck area, sqft (0 = none).
OpenPorchSF Open porch area, sqft (0 = none).
sale_price_keur OUTCOME (regression). Sale price in thousands
of euros.
distressed OUTCOME (binary classification). 1 if the sale
was distressed (foreclosure / short-sale /
similar non-normal disposition), 0 otherwise.

Example output: trees_results_example.json is pushed to your
folder. It is NOT a valid submission - it has placeholder
values - but it shows the exact JSON shape (all field names,
array lengths, scalar types). Use it as a template.

TASKS (what you have to produce - HOW is up to you)
1. Predict sale_price on the test set with a single CART
regression tree YOU IMPLEMENT FROM SCRATCH (greedy SSE
splitting, recursive partitioning). Tune max_depth by
5-fold cross-validation FROM SCRATCH over {2..10}. Also
fit one sklearn.tree.DecisionTreeRegressor at
max_depth=3, min_samples_leaf=5, criterion='squared_error',
random_state=0 - submitted alongside your own depth-3
predictions for a tree-equivalence check.
2. Predict sale_price with a random forest YOU BUILD FROM
SCRATCH on top of your Task-1 tree (bootstrap, per-split
feature subset at mtry=4, B >= 200 trees, Mean Decrease in
Impurity importance).
No library trees or ensembles allowed for Tasks 1 and 2.
3. Predict sale_price with a library gradient-boosted
regressor. You choose the library and tune hyperparameters
yourself.
4. Predict the probability that each test property is a
distressed sale, with a library RANDOM FOREST classifier.
The label is imbalanced - you must declare and implement
an imbalance-handling strategy (see imbalance note below).
5. Same as Task 4 with a library GRADIENT-BOOSTED classifier.
Imbalance handling is required here too.

Imbalance note. The classification components are scored on the
CROSS-ENTROPY of your predicted probabilities against the
TRUE probability function. Choose and declare your strategy
in rf_clf_imbalance_method.

===========================================================
GRADING
===========================================================
Final = 0.70 * Performance + 0.20 * Slides + 0.10 * Code
Slides / Code: submitted = 100, missing = 0.
Performance: 5 components (no ceiling).

1. CART vs library tree agreement (10%)
Relative RMSE between tree_pred_test and tree_lib_pred_test
normalised by range(y_test). Breakpoints:
<0.001 -> 100; ~0.05 -> 50; >0.20 -> 0.

2. Regression ensembles test MSE (30%)
2a) Random forest test MSE (50% of component 2).
2b) Gradient-boosting test MSE (50% of component 2).
Each scored on a linear null -> anchor scale (see below).

3. Classification probability quality (30%)
3a) RF cross-entropy vs true probability (50% of comp 3).
3b) GBM cross-entropy vs true probability (50% of comp 3).
Threshold tuning does not move this; calibration does.

4. Regression variable importance (15%)
4a) Random forest (50% of component 4):
rf_reg_var_importance vs the anchor RF
Mean-Decrease-in-Impurity vector:
70% Spearman rank correlation + 30% top-5 set overlap.
4b) Gradient boosting (50% of component 4):
gbm_reg_var_importance vs the anchor GBM
Mean-Decrease-in-Impurity vector (same scoring rule).

5. Classification variable importance (15%)
5a) Random forest (50% of component 5):
rf_clf_var_importance vs the anchor RF MDI vector.
5b) Gradient boosting (50% of component 5):
gbm_clf_var_importance vs the anchor GBM MDI vector.

How the score-100 anchor is defined:
- Components 2 and 3: a fixed reference ensemble (configuration
held confidential) is fit on YOUR training data; its test
MSE / cross-entropy on YOUR test set is the score-100 anchor.
NULL anchor = predict mean y_train (regression) / predict
base rate (classification). Beating the reference also
scores 100. You will not be told the reference configuration;
tune your own hyperparameters by cross-validation.
- Components 4 and 5: the anchor is a Mean-Decrease-in-Impurity
vector averaged
over many simulated draws from the data-generating
mechanism (a stable population-level importance pattern).

AI FEEDBACK: After grading you receive brief AI feedback on your
analysis summary. For learning only; does not affect your grade.
